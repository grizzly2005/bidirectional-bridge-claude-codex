# v0.3.1 — Linked tracking launcher correction

This patch includes all [v0.3.0 functionality and installation requirements](v0.3.0.md):
durable execution, cancellation/recovery, schema-v4 safeguards, opt-in delegation tracking,
the canonical skill and GitHub release controls. It remains experimental and pre-1.0.

## Fixed

The tracking launcher compared the command-line path with its resolved module path.
When `npm link` introduced a symlink or Windows junction, those paths differed and the
process exited silently before serving MCP or printing help. The launcher now compares
canonical filesystem paths, as the native bridge launcher already does.

A deterministic regression invokes the observer through an npm-style link, checks its help,
connects over real MCP stdio and verifies the five observation tools without creating the
managed bridge database. The suite now contains 500 checks. The five packaging checks and
eight browser scenarios remain separate gates, rerun in the release workflow.

## Upgrade and verification

Use the [v0.3.1 release](https://github.com/grizzly2005/bidirectional-bridge-claude-codex/releases/tag/v0.3.1).
The asset set matches v0.3.0 with `0.3.1` in each archive filename. All six packages,
internal dependencies and server identities use **0.3.1**. The wire protocol remains
**1.3.0** and the database schema remains **v4**; this patch adds no migration.

Verify SHA-256 sums and GitHub attestations, extract into a separate directory, run
`npm ci`, `npm run build`, then `npm link`. Verify both installed commands:

```bash
claude-codex-bridge --help
bridge-tracking-mcp --help
```

Replace the complete canonical skill after preserving any local version, then reload the
MCP connections. Existing tasks and databases do not move with the installation directory.
An already-running process keeps its loaded modules until reloaded. The private ChatGPT
connection and provider execution still require their own live validation.

No published tag or asset is overwritten. v0.3.0 remains available as a historical
checkpoint; v0.3.1 is recommended for the linked observer command.
