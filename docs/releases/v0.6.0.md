# v0.6.0 — Project resume card, unified setup/doctor CLI and release updater

Pre-1.0 candidate. No performance, token-saving or model-superiority claim is established.

## Identity and compatibility

| Layer | Version |
| --- | --- |
| Root and seven bridge workspace packages / runtime | 0.6.0 |
| Independently versioned `@bridge/web-audit` | 0.1.0 |
| Wire capability marker | 1.6.0 (additive) |
| Writable SQLite schema | 6 (unchanged, no migration) |

New optional fields and tools only: `bridge_resume_project` and `contributed_by` on memory
notes. A 0.5.0 database opens unchanged. Upgrade every native client together and reload its
MCP process.

## Added

- `bridge_resume_project`: a bounded, read-only project resume card for a fresh chat. It
  lists active decisions, verified results (passing canonical checks or intact SHA-256
  references) separately from unverified observations, open tasks and quarantined leases,
  next actions and abandoned tracks. It returns no artifact bodies or runtime handles.
- `contributed_by` worker attribution on memory notes, verified against related tasks and
  referenced artifacts; reads expose `recorded_by` and `resolved_authors`.
- Unified `bridge` CLI: `bridge setup` (idempotent project wiring and central bootstrap),
  `bridge doctor` (per-client verdicts and exact remediation), `bridge update` (GitHub
  Releases check, SHA-256/`RELEASE.json` verification, staged MCP stdio smoke, connected
  project inventory). `bridge update --apply` refuses to replace a Git checkout.

## Changed

- Antigravity installs use `timeoutSeconds: 2400` and load `bridge_server_info` and
  `bridge_resume_project` eagerly.
- The lockfile again lists every `@openai/codex` optional platform package.

## Verification and limits

Deterministic gates (typecheck/build, the full test suite, skills/links/docs/manifest checks,
shared-memory and web-audit smokes, permission tests, release-package tests, `npm audit`)
run against protocol stand-ins. The resume card was exercised over a real native MCP stdio
process on the maintainer's database; no new real `claude`, `codex` or `agy` model turn was
required by this release. `bridge update --apply` was exercised on test fixtures; a managed
installation that is a Git checkout is updated with Git instead.
