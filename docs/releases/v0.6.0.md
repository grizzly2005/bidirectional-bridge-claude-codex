# v0.6.0 — Stable: project resume card, unified setup/doctor/update CLI and Gemini runtime

**Status: stable** (pre-1.0). This release consolidates the experimental v0.5.0 line on top
of the last stable v0.4.0. No performance, token-saving or model-superiority claim is
established.

## Release status

| Release | Status | Notes |
| --- | --- | --- |

Experimental releases are marked as GitHub pre-releases; `bridge update` ignores them unless
`--include-prerelease` is given.

## Changes since v0.4.0 (last stable)

### Runtimes and models (introduced in v0.5.0)

- Third runtime `gemini` over the Antigravity CLI (`agy`), with a legacy Gemini CLI dialect,
  and Antigravity as a manager (`--caller gemini`, `npm run install:antigravity`).
- The Gemini **worker** is disabled unless `--gemini-auth api-key|enterprise` is passed.
  Google's Antigravity FAQ does not support Claude Code/Codex driving a consumer Antigravity
  login; the bridge never does it. A Google AI Pro/Ultra plan is used by running Antigravity
  as the manager.
- Workspace-wide model/effort preferences per runtime (`bridge_get_model_preferences`,
  `bridge_set_model_preference`), `TaskSpec.model` / `effort`, runtime defaults otherwise.
  Native Claude workers no longer force `opus`/`high`.
- Shared `@bridge/runner-adapter` package; delegated-worker guard on the native launcher.

### Delegation and tracking (introduced in v0.5.0)

- Explicit delegation-share workflow in the `using-bridge` skill ("délègue 50 %" is a token
  target, measured per runtime) and a model catalog.
- `by_agent` token totals in `bridge_query_telemetry`; read-only localhost dashboard with
  delegated tokens per runtime.

### Shared memory and project resume

- Shared working memory for Antigravity managers, covered by a Codex ↔ Gemini restart and
  concurrency smoke (`BRIDGE_MEMORY_PEER=gemini`). (v0.5.0)
- `bridge_resume_project`: a bounded, read-only project resume card for a fresh chat —
  active decisions, verified results separately from unverified observations, open tasks and
  quarantined leases, next actions and abandoned tracks; no artifact bodies or runtime
  handles. (v0.6.0)
- `contributed_by` worker attribution on memory notes, verified against related tasks and
  referenced artifacts; reads expose `recorded_by` and `resolved_authors`. (v0.6.0)

### Installation, diagnosis and updates (new in v0.6.0)

- Unified `bridge` CLI (`npm run bridge -- <command>` or `node scripts/bridge-cli.mjs`):
  - `bridge setup`: idempotent wiring of a project's Claude, Codex and Antigravity configs
    to one central installation (no per-project bridge copy); a ready project is left
    byte-identical and changed files keep a `.bak`.
  - `bridge doctor`: read-only per-client verdicts (workspace, SQLite DB, caller identity,
    WSL Codex, stale MCP sessions) with exact remediation.
  - `bridge update`: GitHub Releases check, SHA-256 and `RELEASE.json` verification, staged
    MCP stdio smoke before activation, connected-project inventory, DB backups before a
    migration. `--apply` refuses to replace a Git checkout.
- Antigravity installs use `timeoutSeconds: 2400` and load `bridge_server_info` and
  `bridge_resume_project` eagerly.

## Upgrading

- **Git checkout** (central install cloned from this repository): `git fetch --tags`,
  `git checkout v0.6.0` (or fast-forward `main`), `npm ci`, `npm run build`.
- **Installed from a release ZIP (v0.4.0/v0.5.0):** extract
  `bidirectional-bridge-0.6.0-compiled.zip` (check `SHA256SUMS.txt`), run
  `npm ci --omit=dev` in it, then `node scripts/bridge-cli.mjs update --bridge-home <install>`
  and, if compatible, the same command with `--apply`. Later updates only need
  `bridge update --apply`.
- Then, for each project: `bridge setup --project <dir> --bridge-home <install> --dry-run`,
  the same without `--dry-run`, and `bridge doctor --project <dir>`; reopen the sessions it
  reports as stale.

Deterministic gates (typecheck/build, the full test suite — 772 passed, 7 skipped —
skills/links/docs/manifest checks, shared-memory smokes with Claude and Gemini peers,
web-audit smoke, permission tests, release-package tests, tracking UI in Chromium,

was exercised end to end from a real v0.5.0 compiled ZIP to the v0.6.0 candidate assets,
and refuses a tampered ZIP without touching the installation. The resume card was exercised
over a real native MCP stdio process on the maintainer's database. No new real `claude`,
`codex` or `agy` model turn was required by this release; Antigravity's exact stream fields
remain to be confirmed with a real Gemini worker.
