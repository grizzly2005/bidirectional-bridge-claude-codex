# v0.5.0 — Gemini/Antigravity runtime, model selection and delegation share

Pre-1.0 candidate. No performance, token-saving or model-superiority claim is established.

## Identity and compatibility

| Layer | Version |
| --- | --- |
| Root and seven bridge workspace packages / runtime | 0.5.0 |
| Independently versioned `@bridge/web-audit` | 0.1.0 |
| Wire capability marker | 1.5.0 (additive) |
| Writable SQLite schema | 6 (unchanged) |

New optional fields and tools only: `TaskSpec.model` / `effort`, runtime id `gemini`,
`bridge_get_model_preferences`, `bridge_set_model_preference`, `by_agent` in
`bridge_query_telemetry`. Upgrade every native client together and reload its MCP process.

## Added

- Gemini runtime over the Antigravity CLI (`agy`), with a legacy Gemini CLI dialect, and
  Antigravity as a manager (`--caller gemini`, `npm run install:antigravity`).
- Workspace-wide model/effort preferences per runtime; runtime defaults otherwise.
- Explicit delegation-share workflow in the `using-bridge` skill and a model catalog.
- Read-only localhost dashboard with delegated tokens per runtime.
- Shared `@bridge/runner-adapter` package; delegated-worker guard on the native launcher.
- Shared working memory for Antigravity managers, covered by a Codex ↔ Gemini restart and
  concurrency smoke (`BRIDGE_MEMORY_PEER=gemini`). Gemini workers, like the others, receive
  context from their manager rather than calling memory tools.

## Behavior changes

- Native Claude workers no longer force `opus`/`high`; they use Claude Code's default unless
  a task or stored preference selects a model.
- The Gemini worker is disabled unless `--gemini-auth api-key|enterprise` is passed. Google's
  Antigravity FAQ does not support Claude Code/Codex driving a consumer Antigravity login and
  suspensions have been reported; the bridge never does it. A Google AI Pro/Ultra plan is used
  by running Antigravity as the manager.

## Included local fixes

- BRIDGE-FIX-20261014-01 — rejected Claude verification results are preserved for strict resume.
- BRIDGE-FIX-20261022-01 — Windows-hosted Codex worker on a WSL UNC workspace (ported from the
  local 0.3.1 working tree; Windows/WSL runs not repeated during the port).

## Verification and limits

Deterministic gates (typecheck/build, the full test suite, skills/links/docs/manifest checks,
shared-memory and web-audit smokes, permission tests, release-package tests, `npm audit`)
run against protocol stand-ins. No real `agy`, `claude` or `codex` model turn was executed
for this candidate: provider behaviour, Antigravity's exact stream fields and the effect of
`--mode=plan` must be confirmed on the maintainer's machine. Windows descendants of a Gemini
worker that exited normally are not inspected beyond the closed root process.
